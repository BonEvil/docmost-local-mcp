## Root cause and correction

`DocmostMcpServer::get_info()` previously populated instructions and capabilities,
then used `..Default::default()` for the remaining `rmcp::model::ServerInfo`
fields. In rmcp 0.6.4, `ServerInfo::default()` creates `server_info` through
`Implementation::from_build_env()`. Because that function is compiled inside the
rmcp crate, its build-time name and version are `rmcp` and `0.6.4`, not those of
the consuming Docmost MCP binary. The released binary was authentic; the protocol
metadata source was wrong.

The correction makes identity product-owned and compile-time derived:

- `PRODUCT_NAME`, `PRODUCT_TITLE`, and `PRODUCT_VERSION` are defined by the
  Docmost MCP crate and used explicitly by both Clap and MCP server metadata.
- Cargo, lockfile, npm launcher, documentation, and tests identify `0.9.5`.
- Manifest generation requires its tag argument to equal `v` plus the Cargo
  package version and emits the product name, title, and unprefixed version.
- Every platform build checks the actual release executable's `--version` output
  against the Cargo package and tag before staging it.
- The installer rejects a signed manifest with the wrong product name or a
  dependency-derived/stale product version.

No protocol, tool, authority, authentication, network, or write implementation
was relaxed or bypassed.
